Goal

Replace email-only booking with a real calendar:





Customer picks service, then start date/time



System blocks a duration window based on that service (wash ~45-60 min, ceramic/premium ~3-4 h)



Overlapping windows cannot be booked on the public site



Same day can still have multiple appointments if they do not overlap



Owner manages everything in a separate Next.js admin talking to the Spring API



Keep existing form fields (name, email, phone, car, service category/package, location type, distance, message, locale)

Locked decisions





Slot model: service-driven duration; book a start time; reject overlaps



Public site: stay on current Next.js app; call Spring API



Admin: separate small Next.js app + Spring REST API



Auth: admin JWT only; public booking open with rate limit



DB: PostgreSQL



Timezone: Europe/Ljubljana everywhere

Overlap rule: new booking [start, start + duration) is allowed only if it does not intersect any PENDING/CONFIRMED appointment or admin-blocked range.

Backend (Spring Boot)

Stack: Java 21, Spring Boot 3.x, Web, Validation, Data JPA, Security, PostgreSQL, Flyway.

Tables:





services - code, names, duration_minutes, active



appointments - current form fields + service_code, starts_at, ends_at, status (PENDING/CONFIRMED/CANCELLED/DONE), locale



blocked_slots - admin vacation/travel blocks



admin_users - email + password hash



Postgres exclusion constraint on tstzrange(starts_at, ends_at) for non-cancelled rows so double-booking is impossible under concurrency

Public API (no auth):





GET /api/public/services



GET /api/public/availability?date=YYYY-MM-DD&serviceCode=... - free start times only (no PII)



POST /api/public/bookings - same payload as today + startsAt



Errors: SLOT_TAKEN, VALIDATION, RATE_LIMITED

Availability v1: business hours (e.g. Mon-Sat 08:00-18:00), candidate starts every 30 min, keep start if window fits hours and does not overlap appointments/blocks.

Admin API (JWT): login; list/filter appointments; detail; status/reschedule; blocked slots; CRUD service durations.

Email: move sending from src/app/api/booking/route.ts into Spring (Resend HTTP or JavaMail). Keep owner + customer emails. Contact form posts directly to Spring once CORS is set.

Security: CORS for ashine.si / www / admin / localhost; rate-limit public booking; JWT for admin only.
